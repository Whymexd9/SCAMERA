# NICE: незавершённый перенос ZSL и контекста сцены

Состояние 2026-09-21. Этот документ исправляет предыдущий отчёт о стоковом
брекете в APK 30329. Семь уникальных RAW и успешный NICE/RawTherapee/JPEG
проверены в прежнем APK, но все семь кадров были после нажатия. Стоковая
эквивалентность планировщика не доказана.

## Доказанный разрыв

| Источник | runMode | sceneMode | hdrFlags | tableType | tableId |
| --- | --- | --- | --- | --- | --- |
| Стоковый NICE | 9 | 0xc80000 | 65536 | 4 | 0 |
| SCAMERA Camera2 | 14 | 0 | 2 | 9 | 3 |
| Camera2 с NICE session/repeating тегами | 14 | 0 | 2 | 9 | 3 |

Исходные логи вне Git: reports/phone-ae-context-stock-20260921.log,
reports/phone-ae-context-scamera-20260921.log, reports/nice-scene-probe.txt.
Компактные значения: tools/fixtures/vivo-nice-ae-context.json.
Точный перенос математики на этих входах воспроизводит обе ветви; это не
превращает generic-ветвь Camera2 в выбор сцены стокового NICE.

В camera.qcom.so ReadVivoAECHALParam читает vivo.control.sceneMode в
object+0x837c; ReadVAEPerframeInfo переносит знаковый int32 в state+0xb8.
Дальше исходный AE выводит runMode и выбор таблиц. Проверенная библиотека
SHA-256: 137ac72b364f280d993744cb06cf4e6f297bbe45e1aa3248a3560eafc1ac4020.
Живой производитель сцены и необходимые входы выбора пока не подключены.
Постоянное 0xc80000 не является реализацией автоматического выбора сцены.

## Изменения исходников после 30329

- VivoStockAe принимает только matched контекст NICE, сохраняет историю
  планов для выбора до нажатия и отклоняет generic AE.
- CaptureController требует ZSL для NICE: четыре разных N из RAW-кольца,
  затем три новых запроса L/S/ES. При недостатке подходящих N серия отклоняется.
- Каждый N проверяется по своему vendor gain и выдержке; проверка одного
  произведения недостаточна. ISO не используется как измеренный vendor gain.
- Проверка будущих кадров выбирает слот по роли, а не по индексу запроса:
  индекс 0 будущей серии теперь соответствует L.
- VivoNiceCaptureSequence проверяет границу времени, четыре прошлых RAW,
  три будущие роли и соответствие RAW/result/request.

Это локальная реализация политики 4 past + 3 future, а не доказательство
полного стокового расписания. VCF2 и переключение sensor mode не добавлялись.
RawTherapee sharpening сохранён. На устройстве проверена только защита от
generic AE, без запуска серии: reports/nice-scene-guard-final.txt.
Новая сквозная ZSL-серия не проверена: телефон отключён, пользователь сейчас
не может его подключить. Подготовлен local-tools/NiceZslDeviceProbe.java;
его принудительный scene-routing режим исключительно диагностический.

## Тонмапинг и шумодав

Получена полная исходная TCE-трасса с успешным Process и входом/выходом/LUT:
evidence/tce-device/scamera-tce-trace.DAWMDHB0/trace.log и payloads/.
Остаются непрочитанные per-shot структуры по указателям Process+0x90,
0x98, 0xa8, 0xb0, 0x258, 0x2e0, 0x3a0, 0x3a8, 0x3d0. Старые адреса
нельзя повторно передавать в новую сессию; LUT одного кадра не универсален.
Стоковый TCE пока не интегрирован. Пользователь требует его после завершения
брекета; новый интерфейс якобы стокового тонмапинга не добавлялся.

Имеющиеся экспериментальные настройки NICE шума управляют общей шкалой,
photon/readout компонентами перед VST и нормализацией. Независимые внутренние
регуляторы шумодава/резкости фиксированной нейросети не подтверждены.
Значение нормализации 1.1 согласуется с XML againCoeff; отдельный атрибут
UseVst=1.0 не является достаточным основанием менять его.

## Проверки и граница приёмки

Пройдены check_vivo_nice_ae_context.py, 28 проверок
check_nice_capture_sequence.py, check_nice_legacy_isolation.py, воспроизведение
32 сохранённых нативных планов. Это host-проверки, не приёмка на телефоне.
Java-код приложения и тестов успешно скомпилирован с установленным SDK 36.
CameraResumeTest и VivoStockAePlanTest прошли в Robolectric; журнал:
reports/zsl-unit-tests-maven.txt. Для этих host-тестов исключены сборки
нативных workers (их сборщики требуют Linux/macOS); это не проверка workers
или упаковки APK. Использован локальный Gradle init с Build Tools 36.0.0
и Maven Central для загрузки Android-окружения Robolectric.
Для завершения нужны живой выбор сцены, проверка sensor mode, уникальных
реальных RAW до/после нажатия, соответствия экспозиций стоку и NICE/JPEG.
Потом интеграция TCE, проверки его регулировок и финальный APK из Actions
с проверкой SHA256SUMS. Новый APK не собирался и не опубликован.
