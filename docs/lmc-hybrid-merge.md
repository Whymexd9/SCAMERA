# LMC‑гибрид — склейка Sabre 6.1 × LMC 9.6 × Bento × Shasta

Вариант склейки серии RAW для любых GPU с GLES 3.1 (Snapdragon 8 Gen 1–3 и другие), без нейросети.
Собран из разобранных алгоритмов: ядро слияния Sabre из GCam 6.1 (`research/gcam61/SABRE-FULL.md`),
фронтенд, Bento и Shasta из LMC 9.6 (`research/lmc/LMC96_SpatialRGB_Bento_Shasta_audit.md`),
проект совмещения — `research/lmc/Sabre61_x_SpatialRGB_Bento_Shasta.md`.

Сделано 3 октября 2026; проверено на OPPO Find X7 Ultra (PHY110, SM8650, Adreno 750, без root). Раунд 5
(4 октября 2026: отдельный раздел, тон и шумодав ArkCam, света, горячие пиксели, ядро Sabre 6.1) — ниже и в
`research/hybrid5/IMPL_STATUS.md`. Прежняя попытка для 8 Gen 3 (дистиллированный «студент» нейросети на NPU v75 +
«портативный» путь без модели) удалена: гибрид — единственный путь без модели. Нейросеть vivo NICE на SM8750
осталась в SCAM HDR, это отдельный движок со своим разделом.

## Где включается

Свой раздел «**LMC‑гибрид**» (`lmc_hybrid_screen`, ключ экрана прежний) с главным переключателем
`pref_lmc_hybrid_enabled`, не зависящим от SCAM HDR (`pref_vivo_hdr_enabled` / `pref_vivo_nice_enabled`). С 4 октября 2026
гибрид — отдельный движок, а не вариант SCAM HDR: выбор движка `pref_vivo_nice_engine` удалён, SCAM HDR = только
нейросеть NICE. Маршрут снимка — `PreferenceKeys.isLmcHybridEnabled()`: переключатель (nice_dev `hybrid 0/1`) ∧
совместимый RAW (Bayer или ремозаик SCAMERA, без RAW MFSR) ∧ не поток Quad/Tetra мозаики ISZ (его по‑прежнему
обрабатывает SCAM HDR). Если включены оба, снимает гибрид (лог `NICE_HDR … the LMC hybrid merges this shot`). На чистой
установке гибрид включён везде, кроме SM8750 (`LmcHybridKeys.defaultOn()`, нужен arm64‑v8a). Миграция
`SettingsMigration.migrateLmcHybrid` переносит `pref_vivo_nice_hybrid_*` → `pref_lmc_hybrid_*` один раз и копирует ручки
SCAM HDR, которые гибрид раньше читал (fusion, тон, AE, AgX, резкость, N…), только там, где гибрид реально снимал.

Категории раздела: Основное (переключатель, разрешение, даунсемплер) · Захват (N, Bento, Shasta) · Склейка (отбраковка,
ядро Sabre и веса, Bento/Shasta в склейке, света и горячие пиксели, выравнивание и модель шума) · Света (поканальное
восстановление) · Шумоподавление (движок ARK/LMC или NLM) · Тон (тон ARK и его экран; прежний тон SCAMERA — откат) ·
Резкость (rt | scam | off, множитель RawTherapee) · Диагностика. При выключенном гибриде его пункты неактивны
(«Включите LMC‑гибрид.»); при включённом этапы, которые маршрут гибрида пропускает (RT/AI‑шумодав, ACES, тональный
конвейер, алгоритмы склейки HDR+), показаны неактивными с причиной (`SettingsAvailability`).

Все ключи — `pref_lmc_hybrid_*`, пер‑модульные. Обработка снимка идёт под **профилем снимка**
(`PreferenceKeys.beginShotProfile/endShotProfile` вокруг `HdrxProcessor`, `ThreadLocal` потока обработки — захват следующего
снимка и видоискатель читают живой маршрут): общие узлы SCAM HDR и гибрида (`niceInternalValue/Switch`, `vivoHdrValue`,
`profileKey/profileNumber` — AE в `LinearExposure`, колено в `AgxTone`; фьюжн, despeckle, модель шума, CRE) на снимке
гибрида читают копии `pref_lmc_hybrid_<k>` и никогда — ключи SCAM HDR. `nice_dev.txt` (Android/data/…/files): `hybrid 0/1`
и `hybrid_<ключ> значение` перекрывают настройки гибрида без пересборки; строка без префикса (`fusion_dark_ev 2`) действует
на общий узел в обоих движках.

## Раунд 5: вид как у ArkCam 1.23, деталь Sabre (4 октября 2026)

Цель — «как ARK, но детальнее» (`research/hybrid5/PLAN.md`, `research/hybrid5/IMPL_STATUS.md`). Маршрут поста снимка
гибрида (`PostPipeline.BuildDefaultPipeline`, ветка `vivoNiceRgb != null`, тон ARK — `ArkTone.enabledFor`):

VivoNiceRgb (поканальное восстановление светов) → [HighlightRecovery — на гибриде пропускается] → NiceDenoise
(→ `LmcDenoise`: шумодав финиша GCam / LMC 9.6 с таблицами ArkCam 2.85) → [LinearExposure — только ради Ultra HDR] →
ArkStats → ArkFusion → ArkCombine (тон ArkCam: Smart‑HDR AE, фьюжн на guided filter, OKLab, AgX Custom, деталь Sabre) →
резкость (rt | scam | off) → ArkSharpenGuard → [NiceLocalContrast — только с `ark_texture`] → [LmcCurves — только пресеты
пользователя, без кривой GCAM_MATCH] → HybridFinalResize → RotateWatermark.

С `pref_lmc_hybrid_ark_tone` = выкл. остаётся прежний тон SCAMERA (LinearExposure → NiceExposureFusion → VivoHdrTone /
HeadroomRender → LmcCurves → NiceLocalContrast), с `pref_lmc_hybrid_dn_engine` = nlm — прежний NLM‑шумодав.

* **Света** (`VivoNiceRgb`, `vivohdr/nicergb.glsl` режим `hlModeU = 1`, `hlrecovery/chanprep.glsl`): уровень клипа каждого
  физического канала до WB (пик гистограммы; Bento — k), выбитый канал поднимается по хроматичности локального света
  (блоки 8/32/128 px сенсора), всё выбитое плавно уходит в нейтральный белый на уровне `top`, одиночный цветной канал
  (неон, лазер) не трогается. С флагами клипа воркера (ниже) уровень выбирается попиксельно: 1.0 вне маски Bento, k
  внутри. Настройки: `pref_lmc_hybrid_highlight_recovery` (0–100 %, 100), `pref_lmc_hybrid_highlight_chroma` (0.35).
  `VivoNiceRgb.lastClipWhite` — уровень белого клипа для тона. SCAM HDR (NICE) не менялся.
* **Шумодав** (`LmcDenoise`, `assets/shaders/lmcdn/*`): лапласова пирамида яркости kD8 / хромы {1,3,3,1}, BF3x3 + revert,
  BilateralFilterChroma3x3; пороги — из модели шума кадра и измеренных по уровням G; таблицы по SNR (ArkCam 2.85) с
  предохранителями (`dn_revert_max` 2, `dn_coarse_stock` 0.5, `dn_chroma_floor` 2.75); на сетке 2× пирамида строится с
  масштаба сенсора, затем `final2x`. Лог — строка `NICE_PIPELINE lmc-denoise`. Подробно — `research/hybrid5/impl_nr.md`,
  `review_nr.md`.
* **Тон** (`ArkStats/ArkFusion/ArkCombine/ArkSharpenGuard`, `assets/shaders/ark/*`): порт `smart_hdr` и
  `ef_guided_combine` ArkCam 1.23 (`research/hybrid5/tone_port.md` §7); ключи `pref_lmc_hybrid_ark_*` (умолчания ArkCam
  2.85 X8U), лог `ARK SMART_HDR_STAT …`. Деталь Sabre δ ограничена как у a3 ядра (нет чёрного обода вокруг ламп).
  Подробно — `research/hybrid5/impl_arktone.md`, `review_arktone.md`.
* **Слияние** — пункт 8 раздела «Слияние в воркере».

## Съёмка (CaptureController + `HybridPlan`)

* N‑кадры — из ZSL‑кольца по экспозиции превью (`pref_lmc_hybrid_zsl_frames`, 4–44, по умолчанию 20; воркер
  держит на GPU не больше 32 кадров вместе с Bento и Shasta — лишние дальние N отбрасывает).
* После нажатия (`HybridPlan.build`, порядок: сначала ультракороткий, затем длинные):
  * **Bento** — один или два кадра (`hybrid_bento_frames`, 2 по умолчанию; 1 — как LMC 9.6) с экспозицией N/8
    (`hybrid_bento_factor`, 2–16; при 32 полоса расширения маски вокруг светов берётся из кадра с усилением ×32 и
    шумит), если в последнем ZSL‑кадре есть клиппинг (`hybrid_bento_trigger`, доля 0.0005) или режим «Всегда».
    Усиление снижается первым, затем выдержка. Второй кадр той же экспозиции вдвое снижает шум светов и сдвигом
    рук заполняет пропуски решётки R/B одного кадра (+1 кадр после нажатия, ~25 МБ).
  * **Shasta** — 1–5 кадров (`hybrid_shasta_frames`, 5 по умолчанию) с экспозицией N·2^EV (`hybrid_shasta_ev`,
    1 = ×2 по умолчанию): усилением при выдержке N, как ArkCam 1.23 / LMC 9.6 на этом же Oppo днём (5 кадров, 10 мс ×
    аналоговое усиление 2.22, резкость 97–106 % базы, ни один не отброшен, 82 % пикселей с весом от них).
    Выдержка удлиняется только сверх диапазона усиления сенсора (до 1/8 с с рук, с привязкой к периодам мерцания
    `pref_antibanding_hz_key`). Прежнее правило «выдержка первой» (33 мс × ISO 145 при N = 10 мс) смазывало кадры:
    33–82 % резкости базы, ниже порога 80 % в каждом снимке — длинные кадры не попадали в склейку никогда. Отношение
    экспозиций ниже 1.5 или выше `hybrid_shasta_max_ratio` (32) — кадры не снимаются. Фокус, стабилизация, тип
    съёмки и режимы шумодава/резкости/горячих пикселей всех кадров после нажатия — как у превью, из которого идут N
    (шаблон «снимок» переключал AF в AUTO со сбросом).
  * Без запросов (нет клиппинга, Shasta выключен) снимается один дополнительный N.
* Запросы — ручная экспозиция (`AE_MODE_OFF`), проверка результата с допуском 0.4 EV (`HybridPlan.verify`);
  серия валидируется `VivoNiceCaptureSequence.hybridZsl`.

## Сетка Sabre 2× и размер снимка

Sabre 6.1 умеет сливать на сетке вдвое плотнее сенсора: центры выходных пикселей попадают в позиции x/2 − 0.25,
т.е. четыре субпозиции ±0.25 px на каждый пиксель сенсора, ядро остаётся в пикселях сенсора. В гибриде это
заголовок NCH v11 (`grid` = 1 | 2): при `grid 2` шейдер `kHybMergeMain1` запускается четыре раза на полосу с
`kG.zw` = субпозиция и пишет RGB 2w × 2h (для 12‑МП сенсора — 8192 × 6144, 50 МП). Полосы при 2× вчетверо
короче (`stripCells = 128/g²`), чтобы каждое чтение из GPU было одним отображением ≤ 12 МБ от нуля: Adreno 750
возвращает NULL без ошибки GL на чтениях ≥ 50 МБ и на любых чтениях со смещением (проверено; обход — чанки до
32 МБ и лестница вариантов в `HybridGpu::get`). Расширение ядра базы считается по покрытию в каждой субпозиции;
DNG строится из среднего четырёх субпозиций (сенсорная сетка, 14 бит).

Обработка идёт **целиком на сетке 2×**: `HdrxProcessor` после сохранения DNG переводит `rawSize`/`sensorPix`/
`XPerMm` на размер RGB воркера (`LmcHybridBurst.lastOutputSize`, `Parameters.outputScale` = 2 → радиус резкости
NiceSharpen ×2), и только после всего конвейера, включая резкость, готовый кадр уменьшается до выбранного размера.
Уменьшение делает GPU последним узлом конвейера перед поворотом (`HybridFinalResize`, шейдер
`hybrid/final_resize.glsl`; `Parameters.hybridFinalSize` ← `LmcHybridBurst.lastFinalSize`): буфер результата,
битмап и JPEG‑кодер видят уже итоговый размер, а не 50 МП. Ядра — Lanczos‑3, Bicubic (Lanczos‑2), Area (бокс
шириной в коэффициент с дробным покрытием) и Bilinear, фильтрация в линейном свете (sRGB‑декод/энкод); поддержка
масштабируется с коэффициентом (до 4:1). На Adreno 750 Lanczos‑3 8192 × 6144 → 5184 × 3888 занимает ≈1.0 с
(прежний CPU‑Lanczos на 201‑МБ битмапе — 2.4 с и именно в этот момент приложение убивал LMK при 0.7 ГБ свободных).
Узел освобождает две простаивающие рабочие текстуры перед выделением своей; CPU‑путь `VivoPostDownscale.resizeTo`
остался резервом (срабатывает, только если битмап больше цели). Размеры — классические, кратные блоку JPEG:
4032 × 3024, 4608 × 3456, 5184 × 3888 (`PreferenceKeys.hybridTargetSize`: ширина 4:3 на шаге 64 px; размер сенсора
±10 % считается своим классом, поэтому «12 МП» на 12‑МП сенсоре даёт 4096 × 3072 с супердискретизацией), «2×» —
без уменьшения. Порога по памяти нет (по решению пользователя): пик приложения на 50 МП ≈ входная
текстура float 604 МБ + три рабочие FP16 по 403 МБ + битмапы; буфер результата (604 МБ) освобождается сразу после
загрузки в текстуру (`VivoNiceRgb`, вместо него остаётся прореженная копия для статистик), `availMem` пишется в
лог. На PHY110 при 3.6 ГБ свободных первый прогон 2× без этого убил приложение LMK. Настройки: раздел «LMC‑гибрид» → «Разрешение (сетка Sabre 2×)»
(`pref_lmc_hybrid_output`: sensor | 12 | 16 | 20 | 2x) и «Даунсемплер» (`pref_lmc_hybrid_downsampler`:
lanczos | bicubic | area | bilinear); те же чипы — в шторке быстрых настроек видоискателя («Разрешение» 1× / 12 / 16 /
20 / 2×, «Даунсемплер» Lanc / Bicub / Area / Bilin). Нейросеть NICE эти настройки игнорирует. `nice_dev.txt`:
`hybrid_output 0|12|16|20|2`, `hybrid_downsampler 0..3`; реплей: `grid 2` в `hybrid_tuning.txt`.

Замер (PHY110, ночная серия 21 кадр, реплей): слияние 1× 1.58 с → 2× 3.55 с (×2.25), всего 4.6 с; выход 1× при
`grid 1` побайтово совпадает с прежним (2×2‑среднее выхода 2× отличается от 1× на 1.9 % СКО — субпиксельная сетка,
без рассинхронизации). На устройстве (день, 21 кадр + us): слияние 2× 4.6–5.0 с, клиент 8.2–11.2 с, пост‑конвейер
на 8192 × 6144 4.7–7.9 с (VivoNiceRgb 1.9–2.3, NiceDenoise 1.0–1.2, фьюжн 0.6–1.5, локальный контраст 0.8–1.0,
ресайз 1.0), от нажатия до JPEG ≈ 20 с. Пост‑узлы на сетке 2× должны масштабировать свои окна в пикселях
(денойз, локальный контраст, фьюжн, колено AgX, резкость) — см. «Что осталось».

Сколько кадров нужно Sabre: GCam 6.1 включает Sabre от 7 валидных кадров; выигрыш по детали появляется от
≈12–15 кадров и насыщается к 20–25 (наши дефолты 20 на Oppo, 30 на vivo); на сетке 2× самому узкому ядру (σ≈0.22 px)
нужны 20–30 кадров, иначе срабатывает расширение ядра базы (покрытие < 4) и результат сползает к 1×. Без
субпиксельных сдвигов между кадрами (штатив) Sabre не добавляет деталей.

## Света Bento в тоне (окна, лампы)

Склейка отдаёт в окнах настоящее содержимое ультракороткого кадра (значения до k × белого, k = Bento factor;
реплей серии пользователя: при экспозиции ×1/8 в окне видны горизонт и флаг). «Молочное» пятно, ореол вокруг рамы
и розовая кайма возникали дальше, в нашем тоне, а не в слиянии (гипотеза о клиппинге по отсчётам в переходной
полосе маски опровергнута проверкой и реплеем — маска строится из тех же отсчётов базы и с тем же порогом):

* `VivoNiceRgb` — эвристика «плато» (clipLevel = максимум канала, если ≥ 0.05 % отсчётов в 3 % от него) принимала
  ровное небо в окне за клиппинг и обесцвечивала его верхние 15 %. Для снимков с Bento (`LmcHybridBurst.lastBentoApplied`,
  k и `usClippedRatio` из отчёта воркера) эвристика отключена; нейтрализуется только уровень 0.98·k, и только если
  сам ультракороткий кадр клиппирован.
* `HeadroomRender` — локальное колено AgX сжимало всё выше 0.75 EV над серым по собственному значению пикселя
  (а не по базе σ≈40 px): 3 EV контраста внутри окна превращались в 0.4 EV на самом плоском участке сигмоиды,
  а разница окно/стена 4.3 EV — в 0.7 EV (ореол). Теперь, как в финише HDR+, запас k берёт на себя Exposure Fusion:
  тёмная синтетическая экспозиция `NiceExposureFusion` сдвигается на долю log2(k·displayGain) EV
  (`pref_lmc_hybrid_bento_fusion`; только тон SCAMERA — тон ARK ведёт запас Bento сам: потолок 1.35, roll‑off),
  режим «только осветление» снимается, и карта фьюжна локально опускает окно в
  диапазон с сохранением его контраста. A/B на vivo (ровное небо в окне, k = 7.7): доля 0 — окно 250/255 ровное
  (как раньше, без содержимого); 0.5 — 239 в центре / 242 у рамы, ровное и светлое; 1.0 — 199 в центре / 250 у рамы:
  содержимое в диапазоне, но пирамида Лапласа даёт ореол внутрь окна ≈20 %. По умолчанию 0.5; честное решение для
  1.0 — направляемое (guided) повышение разрешения карты усиления по яркости, чтобы она следовала границе окна. `neutralizeClippedMagenta` для таких снимков пропускается, порог обесцвечивания
  светов — 0.95 (`bentoReal`).
* Шумодав в окне: карта эффективных кадров внутри маски ≈2–3 против ≈23 снаружи, усиление сигмы ограничено
  клампом — теперь настраиваемым (`pref_lmc_hybrid_bento_denoise_max`, 3 по умолчанию, до 12).

Про «ARK‑обработку» LMC/ArkCam: разбор libvf_demosaic.so (LMC 9.6 и ArkCam 1.23beta) показал, что ArkCore — только
видоискатель (Live View): один GLSL‑проход демозаик + 4‑слойный попиксельный «exposure fusion» + AgX/ACES/Uchimura,
вызывается из `DemosaicProxy.processRawBuffer`; `processPayloadHardwareBuffer` — заглушка `mov x0,x2; ret` без
вызовов из Java. Снимки идут через финиш Google (libgcastartup) с патчами констант RamPatcher (`lib_*_key_pro`:
таблицы Luma/Chroma Denoise, Bento, HDRrange, dehaze, резкость) и кривыми тона мода. Материалы:
`research/lmc/arkcore/` (shader_map.md, native_logic.md, java_hook.md, x8u_settings.md, ARKCORE.md) и `research/lmc/arkcam/`.

## Шумоподавление после склейки (настройки)

Раздел «LMC‑гибрид» → «Шумоподавление»: `pref_lmc_hybrid_dn_engine` — `gcam` (по умолчанию, `LmcDenoise`, под‑экран
«Шумоподавление ARK / LMC (Noise Reduction)»: SNR и модель, множители патчера, предохранители, таблицы яркости t1–t5 и
цвета t1–t4 строками «a,b,c,d,e») или `nlm` (прежний NLM: `pref_lmc_hybrid_post_luma` 0.6, `pref_lmc_hybrid_post_chroma`
1.0). Для обоих: `pref_lmc_hybrid_despeckle` (одиночные точки), `pref_lmc_hybrid_bento_denoise_max`. Все читаются через
`PreferenceKeys.hybridValue/hybridSwitch/hybridList` (переопределения `hybrid_<ключ>` в `nice_dev.txt`); у SCAM HDR (NICE)
свои внутренние `post_luma`/`post_chroma`. В «Отбраковке движения» — `pref_lmc_hybrid_boost_value` (×6) и
`pref_lmc_hybrid_boost_threshold` (25), в «Ядре Sabre» — `pref_lmc_hybrid_lut_sigma` (1.414); все три идут воркеру через
`hybrid_tuning.txt` (`boost`, `varianceThreshold`, `lutHiSigma`). В слиянии 9.6 отдельного шумодава нет — шум управляется отбраковкой,
пофреймовой LUT шума и весами A/C; финишные таблицы Luma/Chroma Denoise L1–L5 патчера сопоставлены двум силам
NiceDenoise, а не перенесены числами.

## Затвор как в LMC (UI)

Для ZSL‑снимков SCAM HDR (`hybridZsl`, событие `NiceZslCaptureStarted`) кольцо захвата в видоискателе не
показывается, панели не блокируются, звук затвора один, а миниатюра галереи сразу получает кадр видоискателя
(`PixelCopy` из `GLPreview` → `CameraFragmentViewModel.setProvisionalThumb`), кольцо обработки крутится над ней до
записи JPEG. Захват (нажатие → «shutter free») 0.31 с на PHY110 / 0.39 с на PD2454 против 0.59 с у LMC 9.6 (его
фаза `EndPayloadFrames`); flush HAL оставлен: без него первый кадр хвоста на vivo приходит через 466 мс вместо
236–278 (A/B 3 октября), цена — пауза видоискателя 0.3–0.4 с.

## Транспорт в воркер (NCH v10, `LmcHybridBurst`)

Заголовок 128 Б: `'NCH1'`, версия 11, w, h, cfa, число кадров, white, black[4], флаги (1 — диагностика,
2 — вернуть слитый RAW для DNG, 4 — вернуть флаги клипа), индекс базы (0), сетка (1 — сенсор, 2 — Sabre 2×). Таблица кадров по 32 Б: роль (1 normal, 3 bracketed,
5 ultrashort), отношение экспозиции к базе, ISO, slope/offset шумовой модели кадра (нормированные единицы,
Camera2 `SENSOR_NOISE_PROFILE` своего кадра или выбранный профиль), сдвиг по времени. Далее плоскости uint16
в раскладке сенсора. Базовый кадр — самый резкий из четырёх новейших N в окне 205 мс (как LMC
`ChooseBaseFrameZsl`), он первый. Из коротких кадров берутся ближайший к N/8 и, при `hybrid_bento_frames` 2, ещё
один той же экспозиции (±30 %); остальные отбрасываются. Воркер определяет
формат по версии; серию v9 (старый путь) тоже можно слить гибридом маркером `hybrid-merge`/`SCAM_HYBRID=1`.

Результат: RGB float32 на выходной сетке, затем необязательные трейлеры строго в этом порядке — слитый Bayer RAW
(w·h uint16, флаг 2), карта эффективных кадров (uint8 на выходной пиксель, гибрид отдаёт всегда), флаги клипа (uint8 на
выходной пиксель, флаг 4, только после карты). `VivoNeuralClient` подбирает самую полную раскладку, совпавшую с размером
файла, и раздаёт трейлеры: `VivoNiceBurst.lastMergedDng`, `lastEffectiveFrames`, `VivoNiceRgb.lastClipFlags` (все
обнуляются в начале каждой склейки).

## Слияние в воркере (`cpp/vivo-nice-hybrid.h`, GLES 3.1 compute)

1. **Выравнивание** — одна обратная гомография на кадр (vivo CRE LK/RANSAC, на не‑vivo устройствах —
   комплект из APK), группами по шесть кадров; длинные кадры трекуются по клэмпнутой базе, как раньше.
2. **Shasta‑гейт** — резкость длинного кадра по зелёному 1/4‑guide, нормированная на экспозицию²; ниже
   `hybrid_shasta_sharpness`·базы (0.8) кадр отбрасывается; отношение экспозиций > предела — все длинные.
   Оба балла считаются по одним и тем же пикселям — со средним guide ниже `shastaSat` (0.5) белого и в базе, и в
   длинном кадре: длинный кадр клиппирует света, которые база ещё разрешает, и при раздельных множествах длинные
   кадры яркой сцены получали 10–12 % от базы (снимки 3 октября, 08:07–08:14). Порог 0.5, а не 0.9: guide — среднее
   блока 4×4, и у ярких краёв блок со средним < 0.9 ещё содержит выбитые отсчёты вдвое более яркого длинного кадра —
   срезанные перепады давали 74–77 % при той же выдержке (все кадры отброшены); с 0.5 — 99 %.
3. **Маска Bento** (CPU, по ячейкам 2×2 базы): клиппинг ≥ 0.98 → расширение r = 4 (ромб ∪ кольцо) →
   гаусс σ = 1 (7×7); отказы LMC: доля клиппинга ≤ 0.00039, дыры ≥ 15 ячеек, где ультракороткий кадр сам
   клиппирован, или его доля клиппинга в маске > 0.62. В маске сливаются только ультракороткие кадры (каждый с
   весом A / их число), их R и B после склейки полосы пересчитывает проход `kHybBento`: G склейки × R/G, B/G
   ультракоротких кадров на изотропном ядре σ = 2 px (`hybrid_bento_chroma_sigma`, 0 — выкл.). С ядром 1 px R и B
   идут от ближайшего отсчёта решётки, и на наклонной кромке засвета цвет ступенькой меняется через 2 px —
   оранжево‑синий пунктир (виден уже в простом демозаике RAW). Подоконник пары 2: доля пикселей кромки со
   ступенью цвета > 0.1 — 32 % → 7 %. Программа склейки при этом не меняется: на Adreno 750 любая правка её кода
   (даже одно слагаемое в условии) замедляла склейку в ~15 раз; проход Bento — ~60 мс на 50 МП.
   Проверка кадров Bento (`hybrid_bento_validate`, 2 по умолчанию): проверка LMC идёт для каждого ультракороткого
   кадра, вес кадра в маске — по его собственной валидности; режим 2 считает движением и незасвеченную ячейку базы,
   которую ультракороткий кадр показывает заметно ярче. Синтетика «рука через лампу»: тёмные пиксели в лампе там, где
   рука есть только во втором кадре, 37.5 % → 2.3 %; если рука во всех кадрах — информации нет (нужен инпейнтинг).
   Отказ при движении (`hybrid_bento_motion_max`, 4 % по умолчанию, 100 — никогда): если в лучшем ультракоротком кадре
   движение показывает больше этой доли ячеек маски, Bento не применяется в любом режиме, и в «Всегда». Замеры на 10
   сериях PHY110: рука у экрана ноутбука ночью 8.1 %, неподвижные сцены 0–0.13 %, с рук днём у воды 2.2 %.
3a. **Зиппер базового кадра** (проход `kHybChroma` после склейки полосы, до Bento и кромки): где принято меньше
   `widenBelow` (4) доноров (ветки и листья на ветру — отбраковка оставляет базу одну), R и B базы берутся от
   ближайших отсчётов решётки, и вдоль края цвет ступенькой меняется через 2 px. Доля базы в R (B) становится G склейки
   + взвешенной разностью v − G(отсчёт) настоящих R/B‑отсчётов базы, G в отсчёте — по четырём соседям вдоль края;
   с ограничением диапазоном отсчётов базы (`hybrid_chroma_diff`, `hybrid_chroma_diff_clamp`). Ядро Sabre
   поканальное: расширение σ зиппер не лечит. Синтетика (одна база): края +5.8 дБ PSNR, остаток зиппера ×0.1,
   ровное небо −0.5 дБ. Только эти пиксели пересчитываются, склейка не меняется (+~0.1 с на 50 МП вместе с Bento).
4. **Guide базы** (шейдер): цвет ячейки в sqrt‑домене, дисперсия текстуры по 3×3 ячейкам (без шума),
   структурный тензор по 18 зелёным базы с шумовой поправкой (LMC guide) → ковариация ядра Sabre
   (поперёк/вдоль грани/плоско по кривым SNR GCam 6.1, `snrKernel`).
5. **Rejection** (LMC 9.6, по донорским ячейкам): `D² = max(d² − (N_ref + k·N_cur), 0)`,
   `var = max(2·min(V_ref, V_cur), N)`, `distance = cdm·mean(D²/var)` (cdm 0.2 по умолчанию, LMC 0.07: при 0.07 листья на ветру со сдвигом 0.5–2 px проходили отбраковку — яркостный зиппер), `w = 2^(−distance·boost)`;
   клиппированные ячейки длинных кадров отбраковываются; дилатация 5×5 `(Σ25 − 0.2)/2` с порогом шума
   (`hybrid_dilate_floor` 0.15, чтобы шумовые штрафы не расползались); веса базы и обычных кадров ×(1 − маска),
   карта ультракороткого := маска (замена, как в LMC).
6. **Веса кадров**: `A = min(50, ((TET/TET_b)²·read_b/read_f)^fwe)` (LMC), ультракороткий 1.0; ширина ядра
   `LUTσ(A)` {10 → 1, 30 → 1.414} переведена в ковариацию `C/σ²`.
7. **Накопление** (Sabre 6.1): для каждого выходного пикселя — отсчёты своего цвета всех кадров в окне ±1.5 px
   с весом `exp(−½ dᵀCd) + 5e‑5`, клиппированные отсчёты пропускаются; база добавляется последней с
   расширением ядра там, где доноров мало (Sabre: вес < 4 → ×1.826 σ). Ультракороткий кадр внутри маски сливается
   один, поэтому его ядро — изотропное, σ = `bentoUsSigma` (1.0 px, «Bento: ширина ядра ультракороткого кадра»):
   с ядром по guide базы (поперёк кромки ≈0.22 px) у одиночного Bayer‑кадра остаются дыры в R/B — зелёно‑пурпурная
   «молния» по кромкам пересвеченных рам (снимки 3 октября 08:07–08:14). Отсечка пренебрежимых весов (< 0.002)
   действует только для доноров; база и ультракороткий кадр читают все отсчёты (пол ядра заполняет пробелы).
   Выход — линейный RGB float в единицах
   базового кадра (света до 1/factor выше белого), карта эффективных кадров (код 64 = медиана) и слитый
   Bayer RAW для DNG (с клэмпом по белому).
8. **Раунд 5** (`research/hybrid5/impl_worker.md`; всё включено по умолчанию, у каждой части свой ключ `hybrid_tuning.txt`):
   * `cellClip` (P2) — ячейка 2×2 кадра с любым выбитым сайтом отдаёт все свои цвета в среднее клипнутых (по краю
     пересвета зелёный больше не усредняется только с тёмной стороны): пурпурная кайма у ламп ночью 25 % → 9.5 %.
     Клипнутые отсчёты длинных (bracketed) кадров в среднее клипнутых не входят.
   * Выбросы сайтов (P5: `hotSigma` 5, `hotBaseSigma` 7, `hotCross` 0.35, `hotMaxLevel` 0.03, `hotMaxKey` 30): фиксированный
     шум — по среднему 8 обычных кадров на том же сайте сенсора (двусторонний тест), RTS — по одной базе; только в тёмных
     местах и только ночью; сайт остаётся, если его повторяют соседи других цветов. Флаги сайтов идут в битах 14–15 слов
     RAW (нужен белый < 16384; при 16‑битном RAW P2/P5 выключаются с записью в лог). Цвет, оставшийся без отсчётов
     (штатив: все кадры пропускают один сайт), заполняет решётка базы (`baseFill`). Ночь, мост ISO 6400: красные точки
     > 8σ на МП 38 → 19, синие 17.4 → 2.8; оставшиеся сильные красные — огни сцены.
   * `bentoLmc` (P3) — откат Bento по проверкам LMC 9.6: ошибка яркости |min(GainUp(us) − база, 0)| ≥ 0.9 сужает маску;
     отказ — доля клиппинга, затем 8‑связная дыра ≥ 15 ячеек (us недействителен ∧ база белая), затем доля клипа us > 0.62.
     `largestHole` теперь только метрика; режим Bento 2 пишет `forced; would fall back: …`.
   * Ядро Sabre 6.1 (`sabre61` 0 выкл / 1 всегда / 2 авто, по умолчанию 2: при ключе SNR 6.1 ≤ `s61MaxKey` 30, то есть
     ночью; `s61Mode` 7 = 1 ковариация каждого кадра по его RAW + 2 окно ±1.5 px + 4 расширение базы ниже 4 принятых
     кадров): кривые σ и ключ 6.1. Ночью split‑half SNR выше во всех полосах, днём при одной гомографии на кадр — вдвое
     ниже (узкие ядра подчёркивают остаточный сдвиг), отсюда «авто». Таблица шума 6.1 (`noise_estimates_texture`) не
     декодирована: член Винера разности зелёных — амплитуда (`s61GdNoise`), тензор — varU/4 модели кадра (`s61TensorNoise`).
     К ядру 6.1 не относятся `snrScale` и `rawNoise`; `kernelScale` действует на оба ядра.
   * GPU держит не больше 32 кадров (`kHybridGpuFrames`: массивы геометрии `kCommonShader`); лишние обычные доноры,
     дальние по времени от базы, отбрасываются (`HYBRID FRAMES: N normal donors dropped`).
   * Флаги клипа (A4) — третий трейлер по запросу (флаг заголовка 4, маркер job `clip-flags`, при `SCAM_HYBRID` — ключ
     `clipFlags 1`): биты 0/1/2 — R/G/B из среднего клипнутых, 3 — граница клипа, 4 — маска Bento, 5 — ультракороткий в
     среднем клипнутых. Приложение запрашивает их, пока включено восстановление светов (`LmcHybridBurst.clipFlags()`;
     nice_dev `hybrid_clip_flags 0` — не запрашивать).
   * Цена: слияние +0.5–0.8 с на снимок, из них ≈0.45 с — компиляция 8 программ (кэша бинарников программ нет). Со всеми
     новыми частями выключенными выход побайтно равен прежнему воркеру. Униформы на кадр упакованы (программа слияния —
     304 слота; первая сборка с 544 слотами вешала Adreno 750 до перезагрузки телефона).

Отчёт воркера (`NICE_HDR`): `HYBRID KERNEL` (ядро 6.1 / раунда 4, ключ SNR, «auto»), `HYBRID SHASTA sharpness`,
`HYBRID BENTO`, `HYBRID OUTLIERS` (число сайтов фиксированного шума и выбросов базы, cellClip), `HYBRID FRAMES` (таблица как
у LMC: роль, TET, вес, множитель σ), `HYBRID MERGE FACTORS`, `HYBRID EFFECTIVE MAP`, `HYBRID CLIP FLAGS`, `HYBRID STAGES ms`;
с `profile 1` — время каждого прохода и гомографии `HYBRID H`.

## Quad / Tetra без ремозаика (P14, 6 октября 2026)

Сенсормод без ремозаика (vivo `forceSensorMode` 5/7, OPPO `com.oplus.engineercamera.agingtest.mode.select`, ISZ) отдаёт в
RAW_SENSOR родную мозаику цветных блоков, а метаданные по-прежнему говорят «Bayer». Раньше гибрид склеивал её как Bayer:
фиолетовый снимок с решёткой.

* **Блок потока** меряется по данным (`MosaicBlockDetector` в Java и `detectMosaicBlock` в воркере, одна модель): средние
  64 фаз (y mod 8, x mod 8) центра кадра против моделей блока 1/2/4. Java пишет блок в слово 14 заголовка NCH v11 (0 — не
  ясно: воркер меряет сам; 1 — Bayer; 2 — Quad; 4 — Tetra). Ключ тюнинга `mosaicBlock` (0 авто, 1 Bayer, 2/4 принудительно).
* **Склейка (`hybridReconstructMosaic`)** — замысел GCam 11 QuadBayerRgbMerge: выравнивание по бинированному кадру,
  накопление собственных сайтов каждого кадра в RGB. Без новой программы слияния (`kHybMergeMain1` не тронут): кадр с
  блоком b — это b² обычных Bayer-подкадров (w/b)×(h/b), по одному на положение сайта (a, c) в блоке; подкадр (a, c)
  держит сайт (b I + a, b J + c) каждого блока (I, J) с байеровским цветом блока. Гомография подкадра = гомография
  бинированного кадра + известный сдвиг сайта. Обычное слияние этих подкадров на их сетке 2× накапливает ровно сырые
  сайты в их положениях: RGB w×h у Quad. Ядро работает на решётке цветов мозаики, окно 6.1 не теряет цвет.
* **Отклик классов сайтов** (64 класса y&7, x&7) делится заранее по средним полутонов (`mosaicGain`, разброс на X7U ~1 %).
* **Выход** — сенсорная сетка (w×h): `LmcHybridBurst` для мозаики просит сетку 1; если приложение просило 2×, воркер
  дорастягивает билинейно. DNG — Bayer из RGB.
* **Ограничение:** GPU держит 32 подкадра — у Quad это 8 кадров (база, 5 N, ультракороткий, длинный), остальные N не идут.
* **X7 Ultra:** 1x и 5.9x (Quad 4096×3072) — цвет верный, решётки нет. Амплитуда периодов 2/4 px в яркости
  ≤ 0.01–0.4 % (в тех же кропах прежний путь давал 4–25 %), в JPEG ≤ 0.0006. Слияние 2.1–2.9 с против 6.4 с у
  прежнего пути. Проверка — `research/quad14/lattice.py`.

## Измерения на PHY110 (ночь, палуба, ISO 6400, 1/60)

* 20 N + ультракороткий + 2 длинных: выравнивание 0.8 с, маска 0.1 с, слияние 1.4–1.8 с, всего 2.5–2.9 с
  (прежний путь без модели — 5.5 с).
* Статичная сцена: принятие N‑кадров 0.98 (LMC на том же телефоне — 0.94), шум в плоских зонах 0.82× от
  прежней склейки при равной яркости.
* Длинные кадры (66 мс) на движущемся судне отбракованы по резкости (56 % базы) — LMC в том же месте дал 59 %.
* Шумовая модель Camera2 этого HAL совпала с измеренной по двум кадрам (slope 0.0011, offset 4.6e‑6).

## Форматы RAW

`pref_raw_stream_format` (auto | raw16 | raw10 | raw12): при создании сессии формат RAW‑потока выбирается из
`StreamConfigurationMap` (авто: RAW_SENSOR, иначе RAW10, иначе RAW12). RAW10/RAW12 распаковываются в uint16
при копировании (`Allocator.allocateAndCopyConvert`/`…Convert12`, с биннингом тоже); все потребители работают
с uint16 и уровнями чёрного/белого из характеристик, поэтому склейка не зависит от разрядности.
ZSL‑кольцо, RAW‑видоискатель и оценка клиппинга остаются только для RAW_SENSOR.

  `SCAM_HYBRID=1 ./vivo-neural-worker --nice-capture <job dir с libvivo_nice_cre.so и компаньонами> nice_burst.bin out.f32`
  (job dir: `cre-force-bundled`, `hybrid-merge`, при желании `hybrid_tuning.txt`, `clip-flags`). Реплей (`SCAM_HYBRID` или
  `SCAM_NO_KEEP` в окружении) сохранённую серию приложения не перезаписывает.
* `hybrid_tuning.txt` в job dir / ext files / `/data/local/tmp` (первый найденный) — «ключ значение» для всех параметров
  `HybridTuning`: cdm, boost, boostEnable, varianceThreshold, filterVariance, dilateOffset, dilateScale, dilateFloor,

## Что осталось

* Раунд 5 — список открытых пунктов и проверок на телефоне: `research/hybrid5/IMPL_STATUS.md`.
* Локальное (тайловое) уточнение выравнивания (F6) — пока одна гомография на кадр; из‑за этого ядро 6.1 днём хуже
  ядра раунда 4 и включается только ночью; усиление отбраковки ×6 по неоднородности потока выключено.
* Сетка 2×: окна пост‑узлов заданы в пикселях выхода, поэтому все узлы масштабируются по `outputScale`
  (шаг `pxStep` = 2: окна денойза 8×8/3×3/5×5 и NLM, кольца despeckle, окна резкости и Собеля, 5×5 колена AgX;
  стадии хромы/пятен — на 1/(2s) и 1/(4s) сенсорной сетки; база AgX — 1/16 сенсорной; локальный контраст — +1 уровень
  пирамиды со сдвигом полос, субпиксельная полоса без усиления; фьюжн — на 1/(2s) с гауссовым уменьшением);
  при s = 1 поведение прежнее бит‑в‑бит. Шейдеры проверены офлайн glslc (NDK, `--target-env=opengl`). Проверка на
  vivo (Adreno 830, 2× → 20 МП): дилатация «à trous» (отсчёты через пиксель) годится только для статистик (оценка
  шума, детектор despeckle) — у восстанавливающих операторов (NLM, 3×3 сглаживание остатка, USM/AA резкости, окна
  колена) она расцепляет чётные и нечётные пиксели сетки 2×: блоки 2×2, размазанный текст, «пила» на вертикальных
  гранях. Для них `pxStep` = 1 (как до правок), масштабирование идёт только через размер стадий и уровни пирамиды.
  Имя uniform `step` недопустимо (встроенная функция GLSL) — используется `pxStep`.
* Света Bento: фьюжн с запасом k проверить на дневных сценах с окнами и лампами (ореолы пирамиды, яркость окна).
* GPU‑ресайз: на Adreno координата центра во входном кадре считалась с точностью fp16 при объявленном highp —
  выше 2048 px она шла шагами 2–4 px, во всех 20‑МП JPEG сборок 27015–27021 пиксели повторялись с периодом 4
  (видно как ступеньки и блоки). С 27022 центр раскладывается целочисленно (база + дробь), период исчез.
* Деталь 2× → 20 МП (Oppo, день, 21 кадр): после исправления ресайза и масштабирования RT USM по сетке
  (радиусы ×2, порог контраста /2) средние частоты равны 1×, но тонкая деталь (< 1 px) ниже, чем у 1×,
  увеличенного Lanczos до 20 МП. Супер‑разрешение Sabre пока не даёт прироста: проверить точность выравнивания
  (одна гомография на кадр), ширину ядра на сетке 2× и число кадров с субпиксельными сдвигами.
* Сравнение с LMC 9.6 и GCam 6.1 на vivo (одна сцена, кадры совмещены по гомографии): наш 1× по средним частотам
  (1–3 px) на уровне или выше обоих, по тонкой детали между LMC (выше) и GCam 6.1 (ниже, сильнее шумодав); шум на
  ровных участках как у LMC, у GCam ниже. Визуально у 1× ореолы и цветная кайма на контрастных гранях (резкость),
  у LMC текстура естественнее.
* Длинные кадры на статичной сцене/днём не проверены (ночью на судне отбраковываются по смазу).
* Mali/другие GPU: проверен только Adreno (750); при ошибке GLES воркер падает с сообщением, CPU‑резерва нет.
