# Connected NICE query / request metadata builder

`vivo-vcf-nice-request.h` connects `applyNiceHdrQuery` to the six vendor
metadata payloads generated by the same VAS adapter query. One immutable query
and context now produce a `NiceHdrCaptureBundle` containing both internal
control/RAW descriptors and request payloads. Publication is transactional:
invalid required input does not expose a partially built bundle.

**This does not yet submit a Camera2 request.** The fixed capture controller and
seven-input worker are unchanged. The complete scene/AE query producer and
compatible model dispatch must be connected before these payloads can replace
manual capture. No APK was built for this change.

Donor: `libvivo.vas.adapter.vcf.so`, SHA256
`f5fdf379e0316fee77a0ff7760ef247881e4dfade98f3a7bc8b9b8f93c12e901`.

## Exact vendor payloads

| Vendor field | Layout / original publication |
| --- | --- |
| `vivo.parameter.VivoAlgoAECFrameControl` | 48 floats: EV[16], gain[16], shutter[16]; `10284c..102860` |
| `vivo.parameter.VivoAlgoAECShortFrameControl` | 48 floats followed by **integer bits** of dualRawType in the 49th word; `1028bc..1028d0` |
| `vivo.parameter.VivoAlgoCaptureFrameControl` | Nine integers: query pastCount, futureCount, then seven zero words in this NICE branch; `1026dc..102708`, `1029d8..1029ec` |
| `vivo.parameter.rawHDRParams` | Three opaque caller-provided integers from preview+68 / +2eb8; `102418..102428`, `10275c..102774` |
| `vivo.parameter.niceHdrExpEVMode` | Two integers from adapter+3568; `102930..102948` |
| `vivo.parameter.rawHDRCaptureDrcGain` | Float from preview+3dd0; `1027d8..1027f0` |

The last short-AEC word comes from `str w25,[sp,#2a0]` at `1025c0`; it is not
`float(dualRawType)`. A Java float-array transfer must preserve those bits.

The input arrays use the native layout:

| Domain | EV | Gain | Shutter |
| --- | --- | --- | --- |
| Normal | preview+2d10 | +2d50 | +2d90 |
| Paired short | +2dd0 | +2e10 | +2e50 |
| Alternate | +2ec0 | zero in vendor payload | zero in vendor payload |
| Alternate short | +2f00 | zero in vendor payload | zero in vendor payload |

The alternate branch copies only EV into zeroed payloads. In contrast, the
internal `NiceHdrPlan` preserves initialized gain/shutter values for that same
branch. The builder intentionally keeps these different contracts. Internal
one-frame batch entries must also not be substituted for the seven zero words
in the external capture-control field.

Inactive cells are copied bit for bit, including the complete 16-entry arrays.
Required active values are validated. No gain-to-ISO conversion, shutter-unit
conversion or guessed exposure multiplier is introduced. Negative/zero finite
capture DRC is preserved for downstream native policy rather than clamped here.

## Stock Android boundary

The supplied stock APK's `SuperNightCaptureCommand.executeRawVifVivoRawHdrCommand`
reads the AEC and capture-control vendor arrays from capture metadata and
copies them to request parameters. It separately sets the total request count
and enables ZSL for the first count, disabling it for the trailing second
count. Its private request wrapper also carries ZSL-number-in-request-list.
It does not derive standard manual exposure requests by applying table codes
as EV multipliers. Its third-party raw-HDR branch has other behavior; the two
branches are not interchangeable.

The SCAMERA path still needs an actual matching AE query, correct handling of
that request-wrapper boundary, frame matching and a model for the resulting
series. Writing these payloads into the existing manually exposed sequence
would combine conflicting control paths. The complete TCE call is another
remaining integration dependency; it is not enabled by this metadata builder.

## Verification

```
python tools/check_vivo_nice_request.py /path/to/libvivo.vas.adapter.vcf.so
```

384 executions of original `102410..1029f0` match all six payloads byte for
byte, including alternate branches, inactive array cells, paired-short fields,
integer tail bits, zero batch words, DRC, and raw-HDR/EV context fields. The
oracle intercepts metadata-name lookup, actual publication and logging; it does
not replace the array-building instructions. The portable side also checks
that the internal plan is built from the same query and preserves initialized
AE fields. Invalid counts and paired-short AE are rejected atomically.

This is host boundary verification, not capture validation or a claim that
photographic artifacts are fixed.
