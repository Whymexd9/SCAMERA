# Vivo upscale migration (source only; no APK built)

## Status

| Backend | Implemented | Still required |
|---|---|---|
| Vivo RAISR 1.1.56 | Experimental isolated worker; real Init/Process/Uninit calls; capture pipeline replaces Nano RAISR; firmware/filter SHA-256 gate; stock ISO-based profile selection; YUV conversion; timeout and original-image fallback | Android compile and phone execution; color order/range and visual quality validation |
| SoftPQE V2.19.0 | Experimental main-camera ×2 capture path; real Init/Process/GetMode/Uninit; canonical VAF init construction; 21-file SHA gate; bypass/error fallback; backend selector | Device execution, format/range verification, stock capture metadata, visual/latency/memory validation |
| Qualcomm MFSR | Pinned SM8750 registration ABI, ten pipeline stages and factory dependency recovered; registration probe implemented and original entry point emulated | CamX/CHI request/metadata/buffer/session integration; multi-frame capture graph; device execution |

**These are not three completed functional ports.** RAISR and SoftPQE have experimental capture paths. Qualcomm MFSR has no capture path and no enabled setting. Existing SCAMERA RAW MFSR is unchanged and must not be relabelled as Qualcomm MFSR.

## RAISR replacement

`HdrxProcessor` calls `VivoRaisrProcessor` after PostPipeline and before encoding/gain-map processing. The previous Nano RAISR Java CPU/GPU implementations, shader and three filter banks are removed. Old enable/output-scale preference keys remain compatible. Old filter-bank/mode/strength/halo/alias controls are removed from the menu because they are not parameters of this vendor adapter. Archived preferences are not erased.

The native executable is generated by `buildVivoUpscaleWorker` during a future build, using the same NDK as the neural worker. No APK or Actions job was started for this work. No vendor binaries/weights are added to Git or the APK: this version reads the matching phone firmware via a separate root process. Every job verifies the selected profile, all its filter files, the core library, libc++_shared and libvivolog against the supplied dump before loading them. Modified/different firmware fails explicitly and retains the original image.

Vivo SAT role is not a Camera2 ID. In the pinned RAISR binary, switch table at VA 0x643a0 dispatches role 2 to `raisr_rear_master` and role 8 to `raisr_rear_tele_3x`. The modelPath must be the parent `/vendor/camera3rd/nti/raisr`, not the profile directory. The adapter maps known X200 Ultra Camera2 IDs 3/5 to these roles. Unknown IDs (including wide ID 4) fail with a report; it does not silently use the main-camera profile for the wide camera. This mapping will need extension for custom logical/physical module configurations.

The worker uses a 0x160 init structure and 0x78 VImageEx. Important offsets: height/width 0/4, output height/width 8/12, crop type 0x10, zoom 0x24, role 0x28, modelPath 0x2c, log level 0x130, disable 0x134, ISO 0x138. Image planes 0x10, strides 0x30, scanlines 0x40, byte counts 0x50. The VAF caller at 0x4cd0 passes handle, input descriptor and output descriptor to `vivoRaisrProcess`; Uninit takes the handle directly.

Use crop type 2 for explicit output dimensions. Only 17/18 image formats are accepted by the vendor validator. The experimental app supplies limited-range BT.601 NV21 with code 17 and decodes the same order. The exact vendor enum/color contract still needs device chart validation. Application roundtrip tests cannot prove it.

Inputs/outputs must be even-sized, isotropic 1–4x, within the vendor dimension bounds and a 96 MP application cap. Conversion uses two RGB rows rather than a full additional int[] frame. Output descriptor changes, guard corruption, zero/untouched results, wrong file size, nonzero vendor exit and timeout are failures. The child has a 180-second kernel timeout, client 200 seconds. Reports go to the existing app log and `vivo_upscale_report` preferences. There is no automatic fallback to Nano RAISR, no claim of GPU execution, and no stock-quality certification.

## SoftPQE experimental integration

`pref_vivo_upscale_backend_key` chooses RAISR or SoftPQE under the existing enable preference. Default stays RAISR; the legacy manual scale is disabled for SoftPQE. The shared client invokes the worker with `--softpqe`. The current supported profile is Camera2 ID 3 / SAT master role 2, exact ×2. The original image is kept on root denial, missing/mismatched firmware, unsupported module/size, initialization failure, bypass, process error or invalid output. This is an experimental path, not verified stock-quality processing.

The configuration is the original `config/ui_normal_shot/aigc_24M`, with Y+UV processing and `enableSuperResolution=2`. The original `model` directory contains all nine VDNN models. A 21-file SHA manifest pins the four XML files, nine models, core, VDNN, libc++_shared, vivolog, QNN HTP/System/V79 stub/skel. Other system dependencies must still be ABI-compatible. The ADSP search path is explicitly passed; actual DSP access from the root worker needs a phone test. No weights are copied into the APK.

`vivo-softpqe-abi.h` reproduces all 616 bytes built by VAF at 0x4b80..0x4c20 for the supported metadata. Tests execute those original ARM64 instructions and compare with the compiled C++ builder for three dimension/gain combinations. Init copies this block to handle+8. Init offsets: height/width 4/8, output height/width 0x10/0x14, bit depth/role 0x30/0x34, zoom 0x40, sensor gain 0x64, DRC gain/UI zoom 0x70/0x74, config/model pointers 0x100/0x108, crop 0x240..0x24c, quad 0x250, digital zoom 0x254, optional pool 0x260.

Process takes `(handle, processBlock, outputImage)`. The process block has input Image pointer at 0, three zeroed optional mask records at 8, zero count at 0x188, bit depth 8 at 0x190. Core copies 0x194 bytes; natural structure size is 0x198. Output is caller-owned VImageEx, confirmed from VAF 0x5004..0x5024. GetMode reads handle+0x5dcc; bypass byte at 0x5dc8 is also checked before/after Process. A success return while bypassing is rejected.

**Metadata limitations:** at the final Bitmap stage the original Vivo scene/capture metadata is unavailable. Gain is ISO/100; DRC/UI/digital zoom and two unidentified floating metadata fields are neutral 1.0, full-frame crop, no masks/faces, quad disabled. These choices reproduce a valid wrapper construction but do not prove appropriate tuning for our processed images. The experimental NV21 code 17 / BT.601 limited-range contract, profile suitability, format alignment, model execution and output quality require device verification. Normal mode plus populated output is a validation gate, not proof of stock equivalence.

`tools/vivo-upscale/inspect_qnn_v3.py` retains the nine graph metadata shapes. Y1x has 16 input channels; Y2x/Y4x four; UV five. The adapter delegates packing, tiling and model selection to the actual Vivo core rather than inventing a direct QNN tensor mapping.

## Qualcomm MFSR blocker

The supplied `com.qti.feature2.mfsr.sm8750.so` exports `ChiFeature2OpsEntry` and HWmultiframe feature callbacks, not a standalone image-to-image API. DT_NEEDED includes com.qti.chi.override, CamX utilities/settings/ODS, metadata managers, graphics/buffer and Vivo provider interfaces. The Prefilter/BlendLoop/BlendFinal paths operate on CHI request objects and negotiated formats (including UBWC/P010). Passing an RGB bitmap to the entry point cannot port it. The worker registration probe now calls only `ChiFeature2OpsEntry` and validates its 0x38-byte operations structure. It does not call the factory/query/negotiation callbacks with guessed opaque structures.

For the pinned SM8750 build, registration is VA 0x4f860: size at 0, vendor name at 8, version at 0x10, create/query/vendor-tag/negotiation callbacks at 0x18/0x20/0x28/0x30 (VAs 0x4f8b0/0x4f8c0/0x4fc40/0x4fc50). Original entry-point execution under Unicorn confirms these offsets. The factory allocates a 0x6c8 HWmultiframe object and calls `ChiFeature2Base::Initialize(ChiFeature2CreateInputInfo*)`; query requires a real ExtensionModule/sensor context. Those cannot be replaced by empty allocations.

Ten stage descriptors are present: Prefilter, BlendInit, BlendLoop, BlendFinal, BlendInit_16, BlendLoop_16, BlendFinal_16, Equalization, ML, Postfilter. Four flows cover two-frame, three-frame, Pre64 and Post64 variants. Merely selecting a stage does not provide its sessions, metadata dependencies or buffer managers.

The earlier supplied camera archives also contain the full 6,255,512-byte `com.qti.chi.override.so`; it was examined. `UsecaseSelector::MFSRMatchingUsecase` at 0x57e7a0 returns constant true, so it is not a callable standalone MFSR processor or sufficient activation recipe.

**Remaining integration boundary:** restore the exact CreateInputInfo and stream negotiation contracts, initialize a real CHI context/session and target-buffer/metadata managers, submit an aligned frame series with per-frame capture results/fences, then retrieve the final postfilter output and clean up requests. Alternatively determine a documented-by-binary HAL capture route that constructs this graph itself. No such working route is established yet. The current Camera2/Bitmap pipeline does not supply these objects. Qualcomm MFSR is therefore still not ported as an operational backend.

## Verification performed

- C++17 host syntax/type checks with `-Wall -Wextra -Werror`; ABI static assertions.
- Java 17 compilation against cached Android API jar, using only a logger signature stub. This is not a full Android application build.
- Original ARM64 RAISR parameter-validator execution under Unicorn: valid dimensions accepted; zero input width, zero output width, invalid crop mode and invalid disable value rejected. SHA-pinned binary, no Init/Process inference.
- Original ARM64 profile-path construction under Unicorn: SAT roles 2/8 resolve to master/tele-3x XML paths. Execution stops before XML parsing.
- Six fixed BT.601 NV21 fixtures (black, white, red, green, blue, gray) and RGB roundtrips within two code values. Uses a minimal in-memory Bitmap test double; no vendor inference.
- SoftPQE original VAF init construction vs compiled C++ builder: all 616 bytes match in three cases.
- Worker fault injection using a fake host library: populated output accepted; bypass, vendor error, output overrun and modified descriptor rejected without writing output. This does not execute Vivo inference.
- Original SM8750 ChiFeature2OpsEntry under Unicorn: registration size/pointers validated; all ten stage names read. No CHI factory/session execution.
- XML parse and all 21 SoftPQE firmware hash checks.

For the next APK: test main and tele with a color chart and fine texture, scale 1x/2x, low/high ISO. Verify root denial and firmware mismatch preserve the original photograph. Verify wide reports unsupported instead of applying a wrong profile. For SoftPQE test only main ×2 first; verify normal mode, actual output dimensions, channel order/range, texture, edges, memory/time and failure fallback. Do not mark SoftPQE functional until phone inference tests pass. MFSR requires the missing capture integration before a device inference test.

## 30202 device report: graphics dependency loading failure

The supplied September 19 logs contain three attempts where all 21 firmware hashes pass, followed by `dlopen` failure: system `libgraphicsenv.so` cannot resolve `android::base::Join`. No SoftPQE Init/Process is reached. The launcher incorrectly put vendor directories before system directories in LD_LIBRARY_PATH. Changed to system → system_ext → vendor → vendor/hw, matching the established neural worker's system-first policy. Vendor entry points remain absolute paths and the SHA gates remain intact.

A host dynamic-loader regression reproduces this class of failure using two same-SONAME libraries and confirms resolution with the actual Java launcher's new directory order. Java compilation also checks the launcher. Launch dimensions, backend, library order and exit status now appear in diagnostics. These checks do not establish successful device inference; the repaired APK needs a new phone run.
