# Живой RAW-видоискатель на основе libvf_demosaic

Реализация: 2026-09-18. Источник: предоставленный пользователем `libvf_demosaic(1).so`, SHA-256 `78a01441689f52d0a37d4e1b5a4b9d10e215276d6902ebe5db661453b8684285`.

Перенесена основная GPU-проявка извлеченного shader: CFA, нормализация, bilateral-фильтр обычного Bayer, WB, смягчение цвета пересветов, LSC, CCM, однокадровые тени/света, Oklab, ACES-подобная кривая, gamma/film toe. Замер реализован в Java по гистограммам P10/P50/P98 и ISO; параметры сглаживаются между кадрами, сбрасываются при новой сессии.

Один существующий переключатель «Живой видоискатель» включает RAW-путь. Он работает с Camera2 RAW_SENSOR (16-битный контейнер); принудительное подключение packed RAW10/12 к capture-сессии этим изменением не добавляется. Поддержаны четыре Bayer-порядка, цветные блоки 1/2/4 из настройки ремозаика. Нельзя включать блочный CFA для обычного бинированного Bayer лишь потому, что физический сенсор Quad Bayer.

Вместо жесткой зависимости бинарника от классов LMC используется наш CaptureController и существующий GL-контекст. Результат рисуется непосредственно в видоискатель; промежуточный HardwareBuffer и межконтекстная подмена не нужны. Исходный `.so` не подключен как JNI-зависимость.

## Исправления доставки кадров

- PreviewFrameMatcher сопоставляет Image и CaptureResult по точному timestamp в любом порядке прихода. Учитываются timestamps логической и физической камеры.
- Ожидание ограничено двумя Image, чтобы не блокировать ImageReader. Старые изображения закрываются; при смене сессии очереди очищаются.
- Существующий TimestampFrameRouter продолжает отделять кадры съемки от кадров предпросмотра. RAW кадры съемки не передаются в preview.
- ZSL-кадр после сопоставления возвращается в кольцо; состояние съемки перепроверяется перед публикацией.
- Публикация упаковывает реальные пиксели построчно, не читая отсутствующий padding последней строки. Проверяются уровни, матрица, gains, crop и LSC.
- Сессия инвалидирует старую экспозицию и RAW. Кадр старше 500 мс не показывается; при отсутствии кадра/ошибке GL рисуется обычный ISP-preview.

## Отличия от библиотеки

- Подсветка фокуса считает градиент нормализованного зеленого сигнала. Исходная ошибка с clamp сырых 64 и 900 к одному значению исправлена.
- CFA-фаза сохраняется на границах изображения.
- При ручной экспозиции автоматическое цифровое усиление равно 1, чтобы оно не отменяло изменение выдержки/ISO пользователем.
- Убрано фиксированное ожидание 10/30 кадров при смене модуля: RAW становится видимым после первого пригодного кадра новой сессии.
- При ошибке компиляции/линковки/загрузки renderer не объявляет себя готовым.
- Гистограмма измеряет весь заданный crop, без приоритета лиц и отдельных режимов центрального замера. Это сознательное ограничение текущего адаптера, не полное совпадение всех параметров оригинала.
- Активная кривая — ACES-подобная с исходными базовыми значениями. Ветви других кривых присутствуют в shader, но новый UI выбора ими здесь не добавлен.
- Опциональные LUT/LDC выключены, поскольку профили/коэффициенты для этого адаптера не подключены. Это не отключает существующие эффекты обработки сохраняемых фотографий.
- Отдельный небезопасный CPU processRemosaic из `.so` не используется.

## Проверки

- 19 JVM-тестов: сопоставление в обоих порядках, ограничение очереди, освобождение, изоляция буферов, короткая последняя строка, смена сессии, замер, ручная экспозиция и смежные регрессионные проверки.
- GLES3/Mesa: реальные app-shaders compile/link; 12 сочетаний CFA-порядка и размера блока, включая края; подсветка RAW-границы действительно меняет изображение (96 байтов тестового framebuffer); адаптивная проявка дает разные корректные уровни темной/светлой площадки.
- Java-компиляция измененных production-классов с Android 36 / JDK17 и актуальными зависимостями.

APK и Gradle-сборка не запускались по указанию пользователя. На Vivo X200 Ultra еще необходима проверка в установленном APK: переключение модулей, Фото/Ночь, зум, ручная экспозиция, снятие кадра, выход в галерею/возврат. Синтетические проверки не подтверждают доступность сочетания потоков конкретного HAL или реальный FPS.
