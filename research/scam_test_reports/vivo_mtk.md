Still capture A 6529 (816 B, 34 samples). B 3217 (792 B) and B 3561 (3144 B = 131 samples). Registry 0x80060027 byte / 0x80060026 int32 (B 66247-66248). - risk: Read-only, low risk. The length varies per frame (use gyrodatavalidnum). Units are assumed to be rad/s (|w| <= 0.016 when static). The captureGyroData and captureOisData layouts are only partly decoded.

## P3 vivo X500 Pro Max + X300 - RAW is 10-bit RAW_SENSOR only; MTK RAW keys exist (raw.bpp, raw10.convertfmt...) and are needed to check a 14-bit DCG RAW
- theme: full-res
- confidence: inferred
- evidence: Only output format 0x20 RAW_SENSOR (A 3299). No RAW10/RAW12/RAW_PRIVATE and no maximum-resolution arrays (A 3120-3133). Sizes: 4096x3072 for cameras 0/2/4, 4080x3072 for the teles, 4080x3060 for the front. whiteLevel 1023, dynamicWhiteLevel 1023, black 64 (A 3131, 6132, 6500). Buffer rowStride 8192, pixelStride 2, max sample 319, flat low-2-bit histogram, so true 10-bit (A 6819-6825). com.vivo.RAWInfo {4096,3072,2,2,64,82,10,321} for the main (A 11128) and {4080,3072,2,2,64,28,10,128} for the tele (A 14692): [6] = bit depth 10, [7] = max sensor gain. Request keys (int32, registry B 66347-66375; A 4037-4058): com.mediatek.control.capture.raw.bpp, raw10.convertfmt (also a session key, A 5570), packedRaw.enable, compressedRaw.enable, processRaw.enable, hintForRawInputType, recalculateRawType. None has a template or live value. RAW stream throughput is 21.2 of 30 sensor fps even with 2 buffers; ring depth 60, limited by 62 images of ~24 MB (A 6839-6850).
- recommendation: When a DCG try moves sensorScenario: send request com.mediatek.control.capture.raw.bpp int32 [14], then [16], on the RAW captures. Leave raw10.convertfmt unset (a conversion to RAW10 would drop bits). Accept success only on RawPayloadCheck samples above 1023, not on the reported white level. Do not plan on full-resolution RAW: the 50/200 MP sizes exist only in vivo-private size lists (A 3909, 11209, 14774), not in the Camera2 stream configs.
- risk: The effect of raw.bpp is unknown, and it may be ignored for third-party apps. Wrong values may fail the capture. A 16:9 DCG mode may not deliver 4096x3072.
